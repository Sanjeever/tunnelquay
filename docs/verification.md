# 首版验收记录

本文汇总验证证据、适用范围与待完成项。首版本地验证日期为 2026-11-06，环境为 Windows amd64，Intel Core i5-10400、12 个逻辑 CPU，Go 1.26.0、Node 22.17.0、pnpm 12.16.1。浏览器为 Playwright Chromium。当时正式发行密钥未配置，升级与归档签名验证使用隔离临时密钥。

## 设备密钥认证与迁移回归（2026-11-07）

后端实现为 `4a5e285`，设备管理界面与本节记录同提交。此前实现（截至 `53598af`）只校验共享凭据和随机 48 字符 ID，持有二者可认领离线设备，重复在线拒绝不能证明所有权。该缺陷现由独立 Ed25519 密钥、连接随机挑战和签名验证修复；新登记还需共享凭据，已有设备不再以共享凭据认领。通信协议与数据库格式均升至 2，旧设备由管理员显式迁移，操作见 [迁移步骤](development.md#身份迁移与撤销)。

macOS arm64、Go 1.26.0 执行 `go test ./... -count=1 -timeout=5m`、`go test -race ./internal/... -short -count=1 -timeout=3m` 与 `go vet ./...` 通过。测试覆盖无效签名不能预登记、共享凭据与 ID 冒领、仅公钥冒领、重放签名、签名绑定服务端与握手内容、同密钥重复在线拒绝、已登记密钥不依赖共享秘密当前值、撤销断开转发、撤销后重启仍拒绝，以及挑战发出后撤销再提交有效签名仍不能上线。私钥持久化、损坏不替换、Unix 0600 权限和跳过身份挑战的服务端拒绝也有回归。

迁移回归通过真实 SQLite 事务与转发验证，包含旧身份不能自动绑定公钥、仅管理员可迁移、在线原身份拒绝迁移、写入失败全部回滚、端口与启停状态保留、旧历史身份不改写，以及版本 1 数据库升至 2 时保留旧设备。macOS 全量测试还运行同一密钥身份下的实际客户端替换、退出与重新上线确认。

两端测试程序交叉编译为 Linux amd64 后，在 tyk1 隔离目录原生运行服务端 `-test.short -test.v -test.timeout=90s`、客户端 `-test.v -test.timeout=45s` 均通过。覆盖两种传输的身份验证、拒绝冒领与重放、撤销和显式迁移；`-short` 跳过负载与实际替换。日志保存在 `/opt/tunnelquay-auth-regression-20261107/server-results.log`、`client-results.log`，没有修改 UFW，结束无测试端口监听。

前端构建与 `pnpm --dir web exec playwright test --headed` 通过。真实浏览器载入旧设备数据库快照，在真实管理 API 上选择并核对原/新身份、迁移旧隧道并用原端口完成 UDP 回包；撤销后两条身份记录显示已撤销，客户端退出码为 1。桌面、390px 迁移表单与撤销状态截图已检查，未见整页横向溢出或页面脚本异常。旧快照为隔离夹具，不代表真实生产设备已迁移。

本轮没有把安全升级部署到公网实例或迁移现有 tyk1 历史数据，也未进行 Windows 原生验证、长稳或正式发布。前述公网记录对应各自提交的旧握手，不能作为协议 2 公网验收证据。未知控制请求缺陷继续保留。

同日后续 [8192 字节定向诊断](tyk1-smoke-2026-11-06.md#8192-字节定向诊断) 中，回环取得 10/10、直接公网 3/10、TCP 隧道 2/10、QUIC 隧道 0/10。TCP 目标完整收发十个报文，服务端出口捕获十组共六十个对应 IP 分片，将该路径损失收窄到公网网卡出口抓包点至请求端应用之间。QUIC 另有十个请求仅三个到达目标的损失，具体原因未确认。macOS 接收侧抓包受权限限制，尚未定位具体丢弃节点，UDP 稳定性仍未通过。

随后 [tyk1 本机请求对照](tyk1-smoke-2026-11-06.md#tyk1-本机请求对照与-quic-分片日志) 去掉公网业务往返，两轮 TCP 的 1200、8192 字节均为 10/10，QUIC 8192 字节分别为 4/10、2/10。临时日志构建显示服务端提交九十片，客户端应用接收到六十七片，八个不完整报文在约四十二秒后的清理中仍缺片；两组完整报文均当秒重组。本轮未证明两秒期限过短，丢失范围为服务端提交 QUIC 分片至客户端应用接收层之间，具体节点待定位。诊断没有修改仓库业务代码。

2026-11-07 [两端 qlog 诊断](tyk1-smoke-2026-11-06.md#2026-11-07-qlog-诊断) 中，TCP 三档均为 10/10，QUIC 900、1200、8192 字节分别为 9/10、9/10、1/10。服务端 qlog 记录发出的十九个业务 QUIC 包没有对端匹配收包记录，涉及二十个 DATAGRAM 帧，其中十八个包被发送端判为丢失。没有 DATAGRAM 内部丢弃事件，双方 qlog 收帧数与应用接收片数一致。缺片范围收窄到两端 QUIC 发包与收包记录之间，主机网络栈、公网或 NAT 的具体位置仍待接收侧证据确认。

同日 [可靠流临时构建对照](quic-udp-stream-ab-2026-11-07.md) 按 DATAGRAM → 可靠流 → DATAGRAM 执行，8192 字节分别取得 4/20、20/20、14/20；可靠流另有三来源并发合计 60/60，未见串包或内容错误，但 p95 达约 7.6–8.2 秒。临时构建支持可靠承载的可行性，未修改正式行为、默认值或能力协商，也未覆盖公网业务回程、完整回归与长稳验证。

当前测试含心跳延迟容忍与失联关闭、配置响应期限、停用不等待逻辑流关闭，以及默认跳过的慢链路传输和断线恢复。测试存在与历史运行通过分别记录；执行命令和环境要求见 [行为验证](development.md#行为验证)。先前文档审查依据代码、配置、测试内容和提交记录，没有重新运行程序、构建或测试；后续 tyk1 运行范围以独立记录为准。

## 可靠 UDP 承载实现与回归（2026-11-07）

后端实现提交为 `714f09b`，管理界面与本节记录同提交。新增按隧道选择的 `udp_mode`，默认 DATAGRAM，可显式选择可靠流；可选能力 `udp-stream-v1`、数据通道确认和配置代次一起决定承载。已有 JSON 配置缺少字段时继续按 DATAGRAM 处理。正式行为见 [设计契约](design.md#接入协议)，此前临时构建记录保留当时范围。

macOS arm64、Go 1.26.0 执行 `go test ./... -count=1 -timeout=5m`、`go test -race ./internal/... -short -count=1 -timeout=3m`、`go vet ./...` 通过。回归覆盖 QUIC/TCP、UDP/组合协议、同一接入中的两种承载、多来源 8192 字节内容校验、反复切换承载与目标、保留旧来源、迁移公网端口、停用与删除清理、离线编辑、身份恢复、服务端重启和尊重停用。旧能力对端拒绝可靠配置、失败保留旧配置、回退时重新校验能力，以及缺少可靠流就绪确认均有测试。

macOS 本机最大 UDP 发送限制为 9216 字节，65507 字节发送在系统层返回 `EMSGSIZE`，相关最大数据报子用例明确跳过。为验证该边界，将同一后端实现交叉编译为 Linux amd64 服务端测试程序，在 tyk1 原生执行 `server.test -test.short -test.v -test.timeout=180s` 通过，包含两种接入的三个来源 65507 字节可靠 UDP 回包。Linux 的 `-short` 跳过代表性负载与实际客户端替换；其运行证据保存在 `/opt/tunnelquay-regression-20261107-032345/results.log`。本轮没有修改 UFW，测试临时数据库自动清理，结束无测试端口监听。

管理端执行 `pnpm --dir web build` 通过；Playwright Chromium 有界面模式 `pnpm --dir web exec playwright test --headed` 通过。真实浏览器验证 TCP 表单隐藏承载字段，组合协议默认 DATAGRAM，保存可靠流后期望/生效配置与列表正确回显，并通过真实 QUIC 客户端完成三个来源的 8192 字节 UDP 回包。桌面与 390px 表单截图已检查，未见整页横向溢出或页面脚本异常，截图位于 `web/test-results`。

上述 Linux 原生测试使用本机回环网络，浏览器测试使用隔离的本地进程；此前公网可靠流对照仍对应实验构建。本轮没有把正式实现重新部署到公网，也未执行长稳、正式升级或外部发布验证。可靠模式不构成端到端 UDP 交付保证，公网业务回程的分片问题继续保留。

随后基于 `a0e5450` 完成 [tyk1 正式实现公网验收](tyk1-formal-wan-2026-11-07.md)。Linux 服务端与 macOS 客户端实际跨公网接入，两种接入的 900、1200、8192 字节可靠回包各为 20/20，QUIC 三来源并发合计 60/60；配置切换、真实旧客户端能力拒绝与旧配置保留、端口冲突失败保留、跨代次停用及同身份恢复通过。并发可靠回包 p95 约 13.8–15.3 秒；包含公网业务 UDP 的 900 字节路径仍有缺失，DATAGRAM 为 13/20、可靠流为 16/20。本轮结束恢复原防火墙规则并清理所有测试监听，长稳、升级上传及具体公网丢包节点仍未验证。

## 代表性负载

`TestRepresentativeLoad` 在同一测试进程中运行服务端、5 个客户端（3 个 TCP 接入、2 个 QUIC 接入）、20 条 TCP 隧道与负载。20 个并发连接各发送约 4 MiB 并接收等量回包，合计约 160 MiB。测试期间另有交叉构建，占用同机 CPU。

一次本地观察得到双向合计 35.33 MiB/s，持续约 4.53 秒。随后 100 次新连接的首字节延迟 p50 为 2.68 ms，p95 为 6.80 ms。采样峰值 Go HeapAlloc 为 25.99 MiB，包含服务端、客户端和测试负载，不是独立服务端 RSS。删除隧道并清理后 goroutine 为 78，建隧道前基线为 77。结果用于本地功能与资源观察，不代表公网延迟、丢包环境或生产容量。

资源上限、队列策略与 UDP 交付语义见 [设计文档](design.md#资源边界)。
