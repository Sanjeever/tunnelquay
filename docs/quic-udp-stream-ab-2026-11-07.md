# QUIC UDP 可靠流承载对照

2026-11-07 北京时间 00:31:21–00:40:04 完成准备、运行与清理，随后汇总归档。源码基于 `a30a7ec`，服务端为 tyk1 Linux amd64，客户端与目标为 macOS arm64，环境沿用 [前轮记录](tyk1-smoke-2026-11-06.md)。程序与改动保存在临时副本，仓库业务实现、协议和默认行为未修改。

## 实验方法

业务请求在 tyk1 本机发往 `127.0.0.1:27004`、`127.0.0.1:27001`，分别通过 TCP、QUIC 接入链路访问 macOS 回环 UDP 目标，再原路回包。该拓扑去掉公网业务端口与家中请求端之间的往返，不能替代公网业务回程的 IP 分片验证。

同一组临时构建通过两端显式设置实验环境变量 `TQ_UDP_MODE` 选择承载。DATAGRAM 模式保持现有应用分片；stream 模式复用现有两字节长度帧，在每个 UDP 来源会话对应的 QUIC 双向流中传输。TCP 接入仍使用原 Yamux 流。两端开启 qlog，数据报大小、目标、控制与心跳配置保持一致。

按 DATAGRAM A → 可靠流 B → DATAGRAM C 顺序运行。每轮先跑 TCP 控制组，再跑 QUIC；每档 900、1200、8192 字节各二十个报文，发送间隔 100 毫秒，同一档使用单一来源。发送与接收并行，收到全部报文时结束，否则最后一次发送后等待二十秒。校验来源会话、报文标记、序号及完整内容，统计成功回包 RTT。

每轮使用新的 UDP 请求来源、客户端进程、接入连接和目标端口。服务端重启保留同一测试身份与数据库，轮次之间停用两条测试隧道。该顺序用于降低一次偶然链路变化带来的误判，不能保证三轮公网条件相同。

## 完整性结果

| UDP 负载 | DATAGRAM A | 可靠流 B | DATAGRAM C |
| --- | --- | --- | --- |
| 900 字节 | 16/20 | 20/20 | 17/20 |
| 1200 字节 | 15/20 | 20/20 | 19/20 |
| 8192 字节 | 4/20 | 20/20 | 14/20 |

三轮 TCP 控制组各档均为 20/20，合计 180/180。可靠流 B 的 QUIC 主测试为 60/60；另启动三个独立来源并发发送 8192 字节，每来源二十个，全部完整回包，合计 60/60，没有观察到串包、内容错误或重复回包。

qlog 确认 B 阶段两端没有 DATAGRAM 发送帧，记录到 1415 个 STREAM 发送帧和 95 条 `recovery:packet_lost` 事件，统计包含该轮连接建立、控制、主测试与并发测试。完整回包发生于存在 QUIC 丢包事件的连接中。实验没有修改拥塞控制、接收队列或重组期限。

## 延迟与适用范围

可靠流 B 的单来源主测试观测如下，单位为毫秒。

| UDP 负载 | RTT p50 | RTT p95 | 最大 RTT |
| --- | --- | --- | --- |
| 900 字节 | 101.6 | 326.9 | 416.6 |
| 1200 字节 | 120.7 | 350.1 | 450.9 |
| 8192 字节 | 624.3 | 1414.0 | 1501.3 |

三个来源并发测试的 RTT p50 分别约 3945、4381、4591 毫秒，p95 分别约 7578、8015、8204 毫秒；最大 RTT 约 8206 毫秒。该负载同时增加了发送量、排队、拥塞与重传，未隔离各因素，不能把全部延迟归因于同一流内的顺序等待，也不能据此给出生产容量。

分位数采用成功样本的最近秩算法，RTT 从请求写入前计时，到取得完整正确回包，包含首包建立来源会话的成本。DATAGRAM 未返回的报文不进入 RTT 分位数，因此不能用成功样本的延迟直接判定哪种模式整体更快。

公网状态存在显著变化，例如三轮 TCP 控制组 8192 字节 RTT p50 分别约 1869、864、139 毫秒；DATAGRAM 回包也由 4/20 提高到 14/20。本轮支持可靠流可以改善这条接入链路上的报文完整性，尚未提供稳定的模式间延迟差值、长期可靠性或实时业务体验结论。

## 后续判断与收尾

实验结果支持把可靠流承载作为可选方案继续设计。正式实现需要明确选择粒度、默认值和协议能力协商，保证混合版本明确处理；当前环境变量是两端配对的实验开关，没有协商，不应作为正式接口。可靠模式仍需验证来源会话切换、停用、重连、背压边界和更长时间运行，延迟敏感业务需单独评估。

可靠流覆盖的是客户端与服务端之间的接入段，不能修复公网业务 UDP 最后一段的 IP 分片丢失，也不构成端到端 UDP 可靠交付保证。现有 [设计契约](design.md#接入协议) 保留 QUIC UDP 使用 DATAGRAM 的行为，本轮没有改写该契约。
