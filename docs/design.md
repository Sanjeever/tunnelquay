# 设计与行为契约

本文保存 TunnelQuay 的需求、行为契约与架构取舍。平台验证范围与未完成项见 [验收记录](verification.md)。

## 范围与架构

面向个人自托管、单管理员，代表性规模为约 5 台设备、20 条隧道，这两个数量并非硬限制。服务端集中持有设备、隧道配置、公网端口分配与连接历史；客户端保持纯粹无状态，负责维持接入连接并执行服务端的拨号与升级原语，使后续业务功能演进集中在服务端完成。

单仓库、一个 Go Module，分别构建客户端与服务端。服务端使用 SQLite，管理前端嵌入二进制；客户端依赖不包含数据库与前端。采用单机架构以控制部署成本与资源占用，发布构建关闭 CGO。目录见 [README](../README.md#技术与目录)，依赖及工具版本见 [go.mod](../go.mod)、[web/package.json](../web/package.json) 与锁文件。

服务端使用单个 TCP 端口同时处理管理 HTTP 与客户端 TLS 接入，业务隧道监听额外公网端口。管理界面提供 HTTP，域名和 HTTPS 由用户反向代理处理；客户端直接连接服务端。两个程序均以前台方式运行，常驻由用户配置。

首版交付二进制及管理面板。范围外包括多租户与集群、HTTP 域名路由、P2P 与虚拟组网、远程终端与任意命令执行、系统服务安装管理、自动申请证书、Docker 镜像与安装器。暂不实现 i18n、延迟历史图、目标定时主动健康检查、强制升级或服务端 Web 自更新。许可证选择留待维护者决定。

## 接入协议

客户端接入统一采用 TCP + TLS 1.3 + Yamux 多路复用，服务端通过 cmux 在同一端口将 TLS ClientHello 与管理 HTTP 分流。客户端不保存任何隧道列表或配置状态。

当公网连接或 UDP 会话到达服务端公网端口时，服务端在客户端 Yamux 会话上打开一条新的逻辑流，发送 `dial` 原语（包含 `network` 为 `tcp` 或 `udp`，以及 `target` 目标地址 `host:port`）。客户端拨号本地目标成功后回复 `ok`，随后双方直接在该逻辑流上转发数据：
- TCP 隧道直接双向拷贝字节流，并在一端写入完成时传递半关闭（`CloseWrite`）。
- UDP 隧道为每个公网来源地址建立独立逻辑流会话，流内采用 2 字节大端长度前缀封装每个 UDP 数据报（`WritePacket` / `ReadPacket`），完整保留最大 65507 字节的数据报边界。

控制消息采用 4 字节大端长度 + JSON。协议版本及能力校验独立于编码。未知可选字段忽略，未知控制请求明确返回 `unsupported_message` 错误，必要能力缺失在握手阶段拒绝。消息类型、帧上限、心跳间隔与请求期限以 [protocol.go](../internal/protocol/protocol.go) 为准，传输窗口与保活配置见 [session.go](../internal/transport/session.go)。

程序版本、通信协议版本与数据库格式版本独立维护，来源分别为 [web/package.json](../web/package.json)、[protocol.go](../internal/protocol/protocol.go) 与 [store.go](../internal/store/store.go)，首版协议版本与数据库版本均为 `1`。

接入凭据格式和证书校验见 [identity.go](../internal/transport/identity.go)。客户端在发出共享秘密前验证服务端证书公钥指纹，HTTP 反向代理不参与该信任。设备身份持久化；同身份重复接入明确拒绝，已撤销身份在客户端识别为永久拒绝并退出，网络断线按 [客户端退避策略](../internal/client/client.go) 重连。

业务监听首版使用 IPv4。Windows 设置独占端口绑定，避免与允许复用端口的其他程序竞争。

## 资源边界

转发使用有界缓冲与背压；UDP 会话队列满时丢包。历史积压达到上限时暂停接纳新业务连接，写入中的记录仍计入积压。文件传输独立分流并限制并发，避免拖住控制与转发。当前限制集中在以下实现中，修改时须评估总内存与并发成本。

| 边界 | 实现来源 |

| Yamux 流控窗口与保活配置 | [session.go](../internal/transport/session.go) |
| 业务连接、UDP 来源会话、队列与历史积压 | [forward.go](../internal/server/forward.go) |
| 接入并发与文件传输名额 | [server.go](../internal/server/server.go) |

## 管理界面

产品属于开发者工具后台。参考 [Refero Vercel](https://styles.refero.design/style/f24daf3a-d43f-4dec-85a9-8ac1d5148a03)，采用紧凑管理表格布局。四个入口为隧道、设备、连接、设置；状态色用于真实在线、错误和 RTT。表单保留标签、键盘焦点和操作位置的错误反馈，视觉参数见 [style.css](../web/src/style.css)。

## 配置切换

TCP、UDP、TCP + UDP 三种模式全部由服务端直接管理，无需客户端预确认配置。组合模式共用设备、目标与公网端口号，整体绑定公网监听，任一协议绑定失败立即释放本次资源并返回错误，已有配置与监听继续运行。

目标可以是客户端可访问的本机或局域网 IP、域名和端口。隧道可配置允许访问的来源 IP 或 CIDR 白名单（`allow_cidrs`），服务端在公网 TCP 建连与 UDP 会话创建入口直接过滤来源地址，未命中白名单的来源在服务端直接拒绝，不向客户端发起拨号。修改目标地址、端口或白名单后，新连接与新 UDP 来源会话立即应用新规则，已有 TCP 连接和 UDP 来源会话继续使用已建立的逻辑流，保持原有转发不中断。同端口修改协议时复用已有监听并绑定新增协议，移除协议时关闭对应监听与会话。修改公网端口时切换至新端口监听并关闭旧端口监听。停用或删除隧道时立即关闭关联公网监听与活动连接，不等待远端逻辑流关闭。

逻辑端口分配持久化；手动指定或自动分配后保持固定，直到修改或删除。TCP 与 UDP 分别判断占用，自动分配通过真实绑定确认，并发创建不重复分配。

设备离线时保留配置与端口分配，允许离线编辑。设备重新上线后服务端自动恢复已启用隧道的公网监听，并尊重管理员停用状态。

## 信任边界

管理密码与共享登记凭据独立。首次生成临时密码并强制改密，后续启动保留密码哈希。会话、来源校验与反向代理 Cookie 行为见 [api.go](../internal/server/api.go)。共享登记秘密不出现在普通列表或诊断日志中；接入命令按管理权限提供。该凭据授权新设备登记，不能认领已有设备。

客户端持久化独立 Ed25519 私钥，身份 ID 为公钥原始字节的 SHA-256（64 个十六进制字符）。私钥采用 PKCS#8 PEM，保存在客户端数据目录的 `device-key.pem`。密钥缺失会生成新身份，损坏时明确报错且不替换原文件。保留私钥即可在重启、地址变化和升级后保持身份。

服务端在新设备登记时校验共享秘密。每次接入均发送连接专属随机挑战，客户端签名绑定该挑战、服务端公钥指纹和完整 Hello；服务端验证公钥与身份 ID、已登记公钥及签名后，才持久化登记并上线。重连由已登记公钥验证，不能凭共享秘密、主机名、IP 或可见 ID 认领。实现入口见 [客户端身份](../internal/client/identity.go)、[服务端验证](../internal/server/identity.go) 和 [签名内容](../internal/protocol/identity.go)。

管理员通过 `POST /api/devices/{id}/revoke` 撤销身份，公钥与撤销标记持久化，立即停止该身份的监听、业务连接和接入，服务端重启后仍拒绝该密钥；离线或已撤销设备可通过 `DELETE /api/devices/{id}` 连同关联隧道一并清理。管理员还可通过 `POST /api/settings/credential` 重置共享登记秘密，使旧接入命令失效，已登记设备凭自身 Ed25519 私钥继续正常重连。管理操作实现见 [设备管理 API](../internal/server/devices.go) 与 [设置 API](../internal/server/api.go)。

发行包信任来自预置发布公钥，与服务端 TLS 身份独立。测试密钥不得作为正式发布信任。服务端身份与数据库、客户端身份均须持久化，备份操作见 [开发与部署](development.md#前台运行)。

## 历史与观测

设备在线、监听就绪、目标可达分别表达。目标状态依据实际拨号结果或主动探测（`POST /api/tunnels/{id}/probe`，复用客户端 `dial` 原语拨号后立即关闭）更新。

RTT 由服务端测量应用心跳的响应耗时，无需同步时钟，每个心跳周期更新最近有效值。周期以 [协议常量](../internal/protocol/protocol.go) 为准。设备列表以毫秒显示，≤50 ms 绿色，>50 且 ≤150 ms 黄色，>150 ms 红色；离线或无有效值显示灰色 `—`，可访问名称为“往返延迟 RTT”。

历史包含设备与隧道名称快照、协议、来源地址、当时目标、起止时间、流量、结果和原因，失败建连也留下记录。删除隧道后保留未过期历史。筛选先在数据库执行再分页，时间筛选按连接开始时间，保留期按结束时间计算，为 7 天；进行中连接不因开始时间过期而删除。

流量在内存累计，历史批量入库，清理分批执行，数据库错误明确记录。实时速率包含采样期间已结束连接。异常退出后，未结束记录标为中断，结束时间注明为恢复检测时间。持久化与筛选实现见 [store.go](../internal/store/store.go)。

## 单进程升级

发行清单用 Ed25519 签名，签名覆盖 JSON 原始字节。清单包含版本、协议兼容范围、必要能力、平台、架构、组件、压缩包与解包后程序的大小和 SHA-256。服务端验证签名及压缩包校验值，客户端再次验证并检查解包后的程序。归档只能包含清单指定的唯一程序，不将归档路径直接用作解包目的地。

升级由管理员显式发起。服务端从项目 GitHub Release 下载或导入签名包并缓存，客户端通过现有接入链路在独立逻辑流上拉取，无需直连 GitHub。准备期间转发与控制继续工作。客户端在程序所在文件系统准备文件，使用 minio/selfupdate 替换，报告已安装后退出。外部守护或人工启动新版；新版启动失败由人工恢复。

升级任务保存在服务端数据库。客户端若已处于目标版本则直接报告完成，避免重复替换；新版重新上线后服务端核对设备实际汇报版本与任务目标版本，匹配即确认升级完成。超过 5 分钟未确认的任务标记为升级结果待确认，重新上线版本不符时记录失败。签名、下载或校验失败时原客户端继续运行。
