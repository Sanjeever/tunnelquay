# 设计与行为契约

TunnelQuay 面向个人自托管。服务端持有设备、隧道配置与历史，客户端保持单进程，执行服务端期望配置。首版范围见 [handoff](../handoff.md)。

## 实施状态

已建立两个程序及 React 构建嵌入流程。已实现并以本地端点验证 TLS/TCP、QUIC 接入、TCP 半关闭、UDP 多来源与 32 KB 数据报转发、配置切换、登录改密及历史写入。四个管理页面已接入真实 API，并以 Chromium 检查登录、设备、隧道表单、启停、连接筛选和窄屏布局。Windows 隔离环境已验证签名包实际替换、退出、人工重新启动及原身份版本确认。跨平台发布验收继续推进。

## 接入协议

TCP 接入使用 TLS 1.3 + Yamux，cmux 将 TLS ClientHello 与管理 HTTP 分流。QUIC 使用相同证书和应用协议，TCP 业务通过可靠流，UDP 业务通过 Datagram；TCP 接入的 UDP 使用独立逻辑流、两字节大端长度保留边界。

控制消息采用四字节大端长度 + JSON，最大 1 MiB。首版选择标准库 JSON，避免生成工具依赖，协议版本及能力校验独立于编码。未知可选字段忽略；未知控制消息返回错误；必要能力缺失在握手拒绝。握手 10 秒，应用心跳每 10 秒，控制接收期限 35 秒。程序版本与协议版本 1、数据库版本 1 分开。

接入凭据 `tq1.<base64url>` 包含随机秘密和 SHA-256 SPKI 指纹。客户端在发出秘密前验证证书公钥。设备身份持久化；同身份重复接入明确拒绝，断线按 1 至 30 秒指数退避重连，不切换传输。

QUIC UDP 采用 1000 字节分片，12 字节消息编号/片序/片数头，最多 66 片，重组上限 128 份、2 秒，完整业务数据报最大 65507 字节。重组失效在后续收包时清除，空闲时保留数量仍有界。UDP 来源会话每隧道最多 256，总连接最多 1024；每来源队列 64 包，满时丢弃 UDP 包。UDP 会话空闲 60 秒关闭。文件传输独立使用可靠流。

业务监听首版使用 IPv4。Windows 设置独占端口绑定，避免与允许复用端口的其他程序竞争。连接历史每秒批量更新，待写结束记录上限 4096，达到上限暂停接纳新连接；数据库失败明确记录错误。

## 管理界面

产品属于开发者工具后台。参考 2026-11-06 访问的 [Refero Vercel](https://styles.refero.design/style/f24daf3a-d43f-4dec-85a9-8ac1d5148a03)，采用中性浅色背景、细边框、6px 圆角与 14px 正文字号。将参考的内容展示布局调整为紧凑管理表格；状态色用于真实在线、错误和 RTT。四个入口为隧道、设备、连接、设置。表单保留标签、键盘焦点和操作位置的错误反馈。

## 配置切换

保存期望配置与生效配置分离。组合协议整体准备，失败清理本次资源，旧配置继续运行。新配置接收新连接，旧连接保留原目标。停用或删除跨代次关闭全部关联连接。离线保留逻辑分配，重连同步最新期望状态。

## 信任边界

管理密码与客户端接入凭据独立。接入凭据包含共享秘密和服务端公钥指纹。发行包信任来自预置发布公钥，与服务端 TLS 身份独立。测试密钥不得作为正式发布信任。

## 单进程升级

发行清单用 Ed25519 签名，签名覆盖 JSON 原始字节。清单包含版本、平台、架构、组件、压缩包与解包后程序的大小和 SHA-256。服务端和客户端分别验证，归档只能包含清单指定的唯一程序，不将归档路径直接用作解包目的地。

管理员可下载官方 GitHub Release 或导入清单、签名与客户端归档。单包及程序上限 128 MiB，缓存总量上限 1 GiB；同时准备一个包，每设备同时传输一个文件。下载在独立可靠流执行，转发与控制继续工作。客户端在程序所在文件系统准备文件，使用 minio/selfupdate 替换，然后报告已安装并退出。程序不启动辅助进程或新版本。

任务保存到服务端数据库，本地保存任务号与阶段；重复安装请求不会再次替换。重新上线后核对任务号与实际版本，匹配才确认完成。超过 5 分钟未确认的查询显示升级结果待确认。重新上线版本不符时记录失败，由管理员人工检查。签名、下载或校验失败继续运行原进程。
