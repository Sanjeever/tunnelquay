# 设计与行为契约

本文保存 TunnelQuay 的需求、行为契约与架构取舍。实现与契约的已知差距、平台验证范围见 [验收记录](verification.md)。

## 范围与架构

面向个人自托管、单管理员，代表性规模为约 5 台设备、20 条隧道，这两个数量不是硬限制。集中配置用于解决逐台维护客户端映射的问题。服务端持有设备、隧道配置、端口分配与历史，客户端保持单进程，执行服务端期望配置。

单仓库、一个 Go Module，分别构建客户端与服务端。服务端使用 SQLite，管理前端嵌入二进制；客户端依赖不包含数据库与前端。采用单机架构以控制部署成本与资源占用，发布构建关闭 CGO。目录见 [README](../README.md#技术与目录)，依赖及工具版本见 [go.mod](../go.mod)、[web/package.json](../web/package.json) 与锁文件。

服务端使用同一端口号的 TCP、UDP 接入，业务隧道监听额外公网端口。管理界面提供 HTTP，域名和 HTTPS 由用户反向代理处理；客户端直接连接服务端。两个程序均以前台方式运行，常驻由用户配置。

首版交付二进制及管理面板。范围外包括多租户与集群、HTTP 域名路由、P2P 与虚拟组网、远程终端与任意命令执行、系统服务安装管理、自动申请证书、Docker 镜像与安装器。暂不实现 i18n、延迟历史图、目标定时主动健康检查、自动切换传输、强制升级或服务端 Web 自更新。许可证选择留待维护者决定。

## 接入协议

TCP 接入使用 TLS 1.3 + Yamux，cmux 将 TLS ClientHello 与管理 HTTP 分流。QUIC 使用相同证书和应用协议，TCP 业务通过可靠流，UDP 业务通过 Datagram；TCP 接入的 UDP 使用独立逻辑流、两字节大端长度保留边界。

控制消息采用四字节大端长度 + JSON。首版选择标准库 JSON，避免生成工具依赖，协议版本及能力校验独立于编码。未知可选字段忽略，未知控制请求应明确返回错误，必要能力缺失在握手拒绝。服务端未知请求处理尚有 [待修复缺口](verification.md#已确认的待修复缺陷)。消息类型、帧上限、心跳间隔与请求期限以 [protocol.go](../internal/protocol/protocol.go) 为准，传输窗口与保活配置见 [session.go](../internal/transport/session.go)。

心跳期限与配置请求分别维护。受控停顿暴露出原心跳期限过短、TCP 尾包重传窗口不足，因此延长心跳与传输等待，持续失联仍有界关闭；RTT 按真实响应耗时更新。较旧客户端的传输保活期限不会由服务端配置覆盖，应同步升级客户端后复验慢链路。停用先中断连接读写，逻辑流关闭不阻塞管理锁，避免网络背压拖住管理操作。回归入口见 [行为验证](development.md#行为验证)，公网复验缺口见验收记录。

程序版本、通信协议版本与数据库迁移版本独立维护，来源分别为 [web/package.json](../web/package.json)、[protocol.go](../internal/protocol/protocol.go) 与 [store.go](../internal/store/store.go)。0.x 阶段验证协议，1.0 明确稳定兼容契约；在支持的协议范围内继续服务旧客户端，新增功能按能力启用，安全修复可明确提高最低要求。

QUIC 拒绝接入时，连接关闭信息也包含稳定错误码和中文原因，防止连接终止先于错误消息到达时丢失诊断信息。

断开日志记录控制消息的请求号、发送或等待阶段、耗时、错误类别和实际传输。心跳失败同时记录活动业务连接、累计字节、最近业务活动及 QUIC 拥塞/丢包统计或 TCP 复用状态。TCP 连接历史区分两个转发方向；升级失败记录已传输和期望字节数。日志不包含接入秘密或完整控制消息。

接入凭据格式和证书校验见 [identity.go](../internal/transport/identity.go)。客户端在发出共享秘密前验证服务端证书公钥，HTTP 反向代理不参与该信任。设备身份持久化；同身份重复接入明确拒绝，断线按 [客户端退避策略](../internal/client/client.go) 重连，不切换传输。

QUIC UDP 使用带消息编号、片序与片数的分片重组，保留完整数据报边界。分片或重组丢失时整报丢弃，不承诺 UDP 可靠交付。空闲重组仍须有数量与存活边界。业务来源地址由服务端获取，用于历史；目标通常看到客户端出站地址，首版不透传原来源地址。

业务监听首版使用 IPv4。Windows 设置独占端口绑定，避免与允许复用端口的其他程序竞争。

## 资源边界

转发使用有界缓冲与背压；UDP 队列满时丢包。历史积压达到上限时暂停接纳新业务连接，写入中的记录仍计入积压。文件传输独立分流并限制并发，避免拖住控制与转发。当前限制集中在以下实现中，修改时须评估总内存与并发成本。

| 边界 | 实现来源 |

| 数据报大小、分片与重组、QUIC 窗口 | [session.go](../internal/transport/session.go) |
| 业务连接、UDP 来源会话、队列与历史积压 | [forward.go](../internal/server/forward.go) |
| 接入并发与文件传输名额 | [server.go](../internal/server/server.go) |

## 管理界面

产品属于开发者工具后台。参考 2026-11-06 访问的 [Refero Vercel](https://styles.refero.design/style/f24daf3a-d43f-4dec-85a9-8ac1d5148a03)，将内容展示布局调整为紧凑管理表格，以提高日常操作效率。四个入口为隧道、设备、连接、设置；状态色用于真实在线、错误和 RTT。表单保留标签、键盘焦点和操作位置的错误反馈，视觉参数见 [style.css](../web/src/style.css)。

## 配置切换

保存期望配置与生效配置分离。TCP、UDP、TCP + UDP 三种模式均由服务端管理；组合模式共用设备、目标与公网端口号，整体准备，失败清理本次资源，旧配置继续运行，面板同时显示期望、生效配置与错误。配置代次用于防止迟到回执或旧连接错误污染新状态。

目标可以是客户端可访问的本机或局域网 IP、域名和端口。新连接采用新配置，旧 TCP 连接和 UDP 来源会话保留原目标。停用或删除跨代次立即关闭全部关联监听和连接，离线客户端不能阻止服务端停止公网接入。

逻辑端口分配持久化；手动指定或自动分配后保持固定，直到修改或删除。TCP 与 UDP 分别判断占用，自动分配通过真实绑定确认，并发创建不能重复分配。配置与最近生效状态在数据库保存，用于重启恢复。

设备离线保留配置与逻辑分配，允许离线编辑。重连同步最新期望状态，恢复流程尊重管理员停用。已断开的业务连接由应用自行重连。

同端口修改协议时复用已有监听，再准备新增协议。移除协议后保留既有连接，停止接纳该协议的新来源。公网端口变更时，旧 UDP 监听保留到原会话结束，以便准确回包。监听、配置应用错误与目标连接错误分别记录；旧配置代次的迟到结果不能覆盖新目标状态。服务端重启后优先尝试最新期望配置，失败时恢复数据库中最近成功生效的配置。

## 信任边界

管理密码与共享接入凭据独立。首次生成临时密码并强制改密，后续启动保留密码哈希。会话、来源校验与反向代理 Cookie 行为见 [api.go](../internal/server/api.go)。共享接入秘密不能出现在普通列表或诊断日志中；接入命令按管理权限提供。

设备身份在重启、地址变化和升级后连续。认领已有设备应验证该设备持有的独立秘密或密钥，不能凭主机名、IP 或调用方填入的 ID 认领。当前实现存在 [已确认的身份认证缺陷](verification.md#已确认的待修复缺陷)，此契约仍有效。

发行包信任来自预置发布公钥，与服务端 TLS 身份独立。测试密钥不得作为正式发布信任。服务端身份与数据库、客户端身份及升级状态均须持久化，备份操作见 [开发与部署](development.md#前台运行)。

## 历史与观测

设备在线、监听就绪、配置生效、目标可达分别表达。目标状态依据实际转发证据，无访问证据时未知，UDP 未回包不能直接判定不可达；不主动定时探测目标。

RTT 由服务端测量应用心跳的响应耗时，无需同步时钟，正常每个心跳周期更新最近有效值。周期以 [协议常量](../internal/protocol/protocol.go) 为准。设备列表以毫秒显示，≤50 ms 绿色，>50 且 ≤150 ms 黄色，>150 ms 红色；离线或无有效值显示灰色 `—`，可访问名称为“往返延迟 RTT”。

历史包含设备与隧道名称快照、协议、来源地址、当时目标与配置代次、起止时间、流量、结果和原因，失败建连也留下记录。删除隧道后保留未过期历史。筛选先在数据库执行再分页，时间筛选按连接开始时间，保留期按结束时间计算，为 7 天；进行中连接不因开始时间过期而删除。

流量在内存累计，历史批量入库，清理分批执行，数据库错误明确记录。实时速率包含采样期间已结束连接。异常退出后，未结束记录标为中断，结束时间注明为恢复检测时间，未刷新的流量可能不完整。持久化与筛选实现见 [store.go](../internal/store/store.go)。

## 单进程升级

发行清单用 Ed25519 签名，签名覆盖 JSON 原始字节。清单包含版本、协议兼容范围、必要能力、平台、架构、组件、压缩包与解包后程序的大小和 SHA-256。服务端验证签名及压缩包校验值，客户端再次验证并检查解包后的程序。归档只能包含清单指定的唯一程序，不将归档路径直接用作解包目的地。

升级由管理员显式发起。服务端从项目 GitHub Release 下载或导入签名包并缓存，客户端通过现有接入链路获取，无需直连 GitHub。下载在独立可靠流执行，准备期间转发与控制继续工作。客户端在程序所在文件系统准备文件，使用 minio/selfupdate 替换，然后报告已安装并退出。保持单进程以减少部署和恢复复杂度，外部守护或人工启动新版；新版启动失败由人工恢复，不引入升级助手、自动回退或自行启动新版。

任务保存到服务端数据库，本地保存任务号与阶段；重复安装请求不会再次替换。重新上线后核对任务号与实际版本，匹配才确认完成。超过 5 分钟未确认的查询显示升级结果待确认。重新上线版本不符时记录失败，由管理员人工检查。签名、下载或校验失败继续运行原进程。
