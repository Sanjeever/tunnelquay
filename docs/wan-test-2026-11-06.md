# sg1 公网试运行记录

测试日期为 2026-11-06。服务端部署到用户授权的腾讯云新加坡 sg1，系统为 Ubuntu 24.04 x86_64。客户端运行在本机 Windows amd64；另在 sg1 运行 Linux amd64 客户端，验证原生程序与外部守护行为。部署源码提交为 `d5e8429`，服务端版本 `0.1.0`，升级目标为测试专用 `0.1.1+sg1-test`，项目发布版本没有变更。

本文保留该提交下的公网原始观察与收尾状态。后续修复及复验边界见 [验收记录](verification.md#后续修复与验证边界)，以下结果不代表当前提交或服务器现状。

## 测试部署

- 服务端接入为 TCP/UDP 7000，业务端口范围为 27000–27009。
- 测试目录为 `/opt/tunnelquay-wan-test-20261106`，使用独立数据库、身份与临时发行公钥。
- 服务端通过临时 systemd 单元 `tunnelquay-wan-test.service` 运行，设置 `Restart=always`、256 MiB 内存上限与受限文件权限。该单元没有设置开机启动。
- 使用独立测试客户端身份，目标服务绑定本机回环地址。Linux 客户端连接同机服务端，Windows 客户端通过公网连接。
- 未修改服务器原有 OpenResty、1Panel、容器、数据库或防火墙配置。正式签名私钥未生成或配置；测试私钥未上传服务器。

## 公网链路限制

UDP 大报文没有通过本次公网验证。为避免将链路问题和转发实现混为一谈，另外在 sg1 的 27008 端口运行直接 TCP/UDP 回包服务，绕过 TunnelQuay 对照。

| UDP 负载大小 | 直接回包收到 / 发出 |
| --- | --- |
| 64 字节 | 2 / 3 |
| 512 字节 | 1 / 3 |
| 1200 字节 | 2 / 3 |
| 1400 字节 | 1 / 3 |
| 8192 字节 | 0 / 3 |
| 65507 字节 | 0 / 3 |

业务隧道抓包对照中，sg1 网卡没有观察到 8192 字节和 65507 字节的对应请求。直接回包也复现丢失，因此这条路径存在 TunnelQuay 之外的 UDP 丢包或大报文限制。样本数量较少，不能据此给出长期丢包率，也没有定位到具体运营商、路由器或云侧规则。

独立进行的可靠流校验完成 64 KiB 与 256 KiB 数据，TCP 隧道分别耗时约 11.32 秒、9.75 秒，QUIC 隧道分别约 6.75 秒、12.83 秒。直接 TCP 回包分别约 1.57 秒、5.56 秒。数据经过不同数量的网络路径，这些数字不作为协议吞吐对比或生产容量结论。

两条接入同时进行 1 MiB 传输时，TCP 完成，QUIC 在中途断开并自动重连。后续 TCP 长文件传输也出现中途关闭，3 MB 文件曾在收到约 2.24 MB 后结束。另一次升级后 TCP 复核触发测试端的 12 秒空闲超时，服务端历史记录显示该连接只返回了目标横幅，没有开始上传校验负载；不能将这次复核记为完整传输通过。连接日志和历史保存了这些失败，当前慢链路下的大文件连续传输稳定性尚未通过验收。需要进一步区分链路停顿、心跳/写入超时和传输背压的影响。

## 升级及收尾

公网管理 API 上传 Windows 测试包的请求在 120 秒内没有得到完成响应，SSH 传包也发生超时。对已收到的文件核对前缀校验值后，通过 TCP 业务隧道和 SSH 补传剩余部分。两个测试包的完整 SHA-256 校验通过，均出现在服务端已验证缓存中。Linux 包在服务器本机通过管理 API 导入。公网上传超时保留为未正常完成的路径，不用后续补传结果替代它。

| 平台 | 替换、退出与重新上线结果 |
| --- | --- |
| Windows amd64 | 使用 TCP 接入，实际替换文件后以退出码 0 退出；此时任务为 installed，未提前标记 completed；测试编排重新启动后，原设备身份上报 `0.1.1+sg1-test`，服务端确认完成 |
| Linux amd64 | 使用同机 QUIC 接入，实际替换文件后退出，由外部 systemd 的 `Restart=always` 重新启动；观察到 NRestarts=1，原身份上报新版本，服务端确认完成 |

独立核对了替换后的程序文件。Windows SHA-256 为 `8a488d9c9d13db67a8e5a63a4a464854eb41c499af02482bbd6089698bb42351`，Linux 为 `367c60add834cfd761156b74a2e844bc02800674fd7793bd533027846222c0c8`，均与签名清单的二进制哈希一致。新版 Windows 客户端恢复了离线期间更新的 HTTP 目标配置并完成请求；Linux 新版的 TCP 目标回包通过。完整数据加载后的设备页同时显示了两个升级后的测试版本。

收尾时停用七条业务测试隧道，删除临时传包隧道，停止本机客户端、目标及传包进程，并停止 sg1 的 Linux 测试客户端和回包服务。最终检查仅剩服务端 TCP/UDP 7000 监听，27000–27009 没有测试监听。服务器上的测试登录明文文件和 Cookie 文件已删除；测试目录权限为 0700，数据库、日志与测试包保留供核对。管理端继续运行，尚未配置开机启动。

本轮仅验证 IPv4 公网路径。IPv6、其他系统架构、正式签名信任及公开 Release 下载尚未验证。基础功能和两平台实际升级完成，公网 UDP 大报文与慢链路长传输稳定性没有通过本轮验收。
